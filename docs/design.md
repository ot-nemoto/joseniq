# 方針と決まり

JOSENIQ を作るうえで決めたことをまとめる。動きや決まりを変えるときは、この文書も同じ PR で直す。

## 守る決まり

### 武将の能力は、攻めと守りで同じにする

武将の能力値は、攻める側と守る側でいつも同じにする。釣り合いが崩れても、片方の武将だけを弱めたり強めたりして直すことはしない。釣り合いは、兵種・施設・配置・AI の動き・編成例などで取る。
- 能力値とは、`src/sim/defs.ts` の `GENERALS` に書く値（体力・威力・撃つ間隔・速さ・射程・範囲攻撃・スキルの値（`skillCd`・`skillWindup`・`ward`・`wardTime`・`spin`・`spinRadius`）などと、`GeneralTraits` の特徴の値）
- 能力値は `GENERALS` に1つだけ書き、守り（`GDEF`）と攻め（`ADEF`）の両方がそれを広げて使う。`GDEF`・`ADEF` の側で、`GENERALS` から来た値を上書きしない（上書きしても型は通る。攻守で値が食い違えば `src/sim/defs.test.ts` が落ちるが、両方で同じ値に上書きしたときは気づけないので、書くときに気をつける）
- `GENERALS` の外にあって、片方の側にしか意味のない値は、能力値ではなく、その側での動かし方の設定。守りの `aggro`（敵を見つける範囲）・`leash`（持ち場から離れられる距離）と、攻めの `fac`・`gate`・`hall`（施設・門・本丸への倍率）・`pref`（狙うものの好み）・`reach`（兵の寄り道の距離）・`cost`・`limit` がこれにあたる。この決まりの外だが、変える前にユーザーに確かめる。攻めの表の `name`・`glyph` は、武将の名前とその1字目を入れる表示のための値で、これも能力値ではない
- 上に挙げていない攻めの値（守将への倍率 `vsGen`、当てた相手を遅くする `slow`、兵を相手にしない `noUnits` など。今は兵の行だけが使う）を武将に持たせるときは、能力値として `GENERALS` に書き、攻守の両方に持たせる

### 武将の新しい特徴は、その武将がいない戦いを変えない

武将に新しい特徴を足すときは、その武将が出ていない戦いの結果が変わらないように入れる。編成例の勝ち負けが変える前と同じかを、`npm run balance` の結果を比べて確かめる。

### 数値は仮

兵種・施設・武将の数値は、今はどれも仮の値。数値の調整は、基盤づくりがひと段落してから行う（下の「進め方」）。仕組みを足したときに釣り合いの実績（`npm run balance` や `npm run balance:combos`）を取るのは、影響を見るためで、その結果からすぐに数値や配置を直すことはしない。

### 城の配置は、現実の城にない形を許さない

開戦前の確かめ（`notReady`）で、現実の城にない形を止める。守りが強すぎる配置は、たいてい現実にない形から生まれるため。
- 櫓・大筒・鼓楼・鐘楼は、本丸から守り手が歩いて行ける所に、縦か横で面していること（`unmannedFacilities`）。現実の櫓は郭の内側から兵が出入りするので、まわりを城壁などで閉じた、だれも入れない櫓はない。閉じた櫓は近くで攻撃する兵に壊されないので、許すと守りが強くなりすぎる
- 門は、縦か横のどちらかの向きで、前後のマスが空いた陸であること（`blockedGates`）。門は人や荷が通る口なので、前後をふさいだ門や、前後が川・堀の門はない。門の前を1マス陸にして、その先に堀を引く形（土橋）は認める
- 塀と郭（`castleShape`）。城は、塀で囲った郭の中に本丸を置き、郭には門から出入りする。本丸への一本道や迷路のように、塀を道の壁として使った城は現実にない
  - 郭は、城壁・門・施設・崖で区切った空き地のひとまとまり。川と堀は、入れるので郭を区切らない（郭は川や堀をまたいで続く）。盤面の外周に出られるものは郭ではなく城の外。施設に面していない、崖だけで閉じた台地は、城と関係のない地形なので郭に数えない。本丸から門をいくつくぐって入れるか（深さ）の順に、二の丸・三の丸…と名前を付ける。本丸を囲まない郭も認め、出丸と呼ぶ。郭の数に上限はない
  - 本丸は塀の中にあること。本丸に（崖をはさまずに）面した空きマスが、門を通らずに外周へつながっていない
  - 城壁・門・櫓は塀の線に置く。塀の線は、縦横斜めの両側が別の郭（または郭と城の外）になる所か、片側が郭でもう片側が崖になる所（崖の上の塀）。野原に置いた城壁や、郭の中に突き出した城壁は塀の線にない。川は郭を区切らないので、川に面した所も城壁で囲う（川の向こうが城の外なら、川岸の城壁は郭と城の外の間の塀になる）。塀や本丸と郭の間が崖なら、面していないとみなす
  - 門と櫓は、先に城壁で塀を作り、その城壁の上に置き換えて置く。消すと城壁に戻り、動かすと行き先の城壁と入れ替わる
  - 大筒・鼓楼・鐘楼は、塀の線ではなく郭の中に置く。大筒は壊せば通れる施設なので、塀に組み込むと門の代わりの抜け道になる。幅1マスの郭に置くと郭が分かれる。郭の外（城の外の野原など）にも置けない（`outsideFacilities`）。点数を払う郭がなく、点数を無視して施設を増やせてしまうため。画面で置くときは止めるが、置いたあとで郭を囲む城壁を消したときや、配置記録の読み込みでは生じるので、開戦前の確かめで止める
  - 本丸から城の外へ、同じ門を通らずに行ける道（逃げ道）を `ESCAPE_ROUTES`（2）本作ること。同じ郭の中を通るのは認めるが、途中まででも同じ門を通るのは認めない。現実の城が門を複数持つのは、大手と搦手のように、片方をふさがれても出入りできるようにするため。ゲームでは守り手にとって門は弱点でしかないので、数だけを決めると最小の数を攻めにくい所に寄せる形になる。行き止まりの郭（腰曲輪など）は逃げ道に関係しないので、門1つでも、外の門がなくても作れる。逃げ道は陸だけを通り、川や堀を渡らない（橋は渡れる）。人や荷が出入りする道なので、川や堀で城を囲んだら、橋のかかった所か陸のまま残した所（土橋）から出る
  - 2本の逃げ道の外の門（城の外と城の中の両方に面した門）は、本丸の真ん中から見て `ESCAPE_ANGLE`（90）度以上開いていること（数値は仮）。隣り合わせの門では、片方をふさがれると両方使えないため。内の門どうしの開きは決めない（門どうしの間かくは、下の `GATE_SPACING` で決める）
  - 外の門は、城の外に面した塀 `WALL_PER_GATE`（50）マスにつき1つ（切り上げ）以上置くこと（数値は仮）。塀は城壁・門・櫓のマスで、川に面した城壁も、川の向こうが城の外なら数える。外の門に数えるのは、逃げ道と同じく、攻め手が陸と橋で出撃できる城の外に面した門だけ。まわりを川や堀で囲んだ陸に面した門は数えない（攻め手は必ず水を渡るので、門の前をじかに川や堀にした門と変わらない。前を1マスだけ陸にして、門の前後の決まりを抜けられないようにするため）。門の総数には上限がない
  - 同じ郭の外周の門どうしは、直線で `GATE_SPACING`（15）マス以上離すこと（`closeGates`。数値は仮）。門は、両側の郭のうち本丸に近い（深さの浅い）郭の外周の塀にあるとみなし（同じ深さなら両方の外周にある）、外周の違う門どうし（二の丸の門と三の丸の門など）は比べない。門の数だけを決めると、門を並べて（1マス空けても）数を満たせるが、並んだ門は1つの口と変わらないため。直線で測るのは、塀に沿って遠くても、角をはさんで近い門は一か所から攻められるため。開戦前の確かめでは、郭の土地と点数のあとに見る（郭の形が決まらないと、門の置き場も決まらないため）
  - 郭ごとに、広い土地を `KURUWA_LAND`（100）マス以上取ること。広い土地は、郭の空きマスのうち、`LAND_BLOCK`（3）×3 以上の同じ高さの空き地（川や堀を含まない）の一部になっているマス。郭は人が住み兵が集まる場所なので、幅の狭い通路だけの郭はない
  - 施設は点数で置く（数値は仮）。郭の点数は、広い土地 `LAND_PER_POINT`（10）マスにつき1点。施設の点数は `BDEF` の `cost`（弓櫓2・鉄砲櫓3・大筒3・鼓楼2・鐘楼1）。郭の中の施設は置いた郭が払い、塀の線の櫓は両側の郭のうち本丸に近い（深さの浅い）郭が払う。近さが同じなら、残りの点数が多い郭が払う。点数が足りない所には置けない。施設の種類ごとの数の上限は置かない（数は点数で抑える）。城壁の数の上限も置かない（塀の線・郭ごとの土地と門・仕切ると土地が減ることで抑える）
  - 攻め手が出撃できる城の外は、どこからも城の門まで歩いて行けること。塀で城の外を切り離し、門のない側から攻め手が近づけなくする形は、現実の城を攻める形にない。この確かめでは、川と堀は渡れないものとして数える（橋は渡れる）。戦いでは渡れても、川や堀で城の外を切り離し、門のない側から近づくには必ず水を渡らせる形を止めるため
  - 開戦前の確かめで道を見るとき（外周から本丸への道・城の外から門への道・逃げ道）は、外周の出撃口どうしを歩けないものとして数え、出撃口は、そこから城域へ入る入口としてだけ使う。出撃口づたいに回り込めば門へ行ける、という形を認めないため。外周から本丸への道も、川と堀を渡らずに見る。戦いの中の動きは変えない（攻め手は出撃口を歩け、川と堀を渡れる）
  - 平城では、堀（`moat`）を引ける。効果は川と同じ（下の「川と堀」）。現実の平城の水堀にならい、川から水を引く形だけを許す
    - 堀は、川（またはもう引いた堀）と縦横でつながる、川と同じ高さのマスにだけ引ける（`moatAstray`）。台地の上の城（平山城・山城）には届かないので、堀が効くのは、川と同じ高さの土地が広い平城になる。現実の平城の水堀・山城の空堀の違いにも合う
    - 川に沿って引いて、川を太くしてもよい。塀からの距離も決めない（野原に引いた堀も認める。数の上限で抑える）。前は、川のすぐそばに引く堀（川と並んで走る堀）を止めていたが、決まりが複雑で分かりにくかったので外した。堀で城をぐるりと囲む形は、城の外の野原から陸と橋で門へ行けることと、逃げ道を陸と橋で見ることで止まる
    - 堀のマス数は、城の型ごとに `MOAT_CAP` まで（平城50・平山城0・山城0。数値は仮）。堀は、平城の特徴として川を活かすためのもの。山城や平山城は高低差を活かした戦い方ができるが、平城にはそれがないので、川を活かす堀は平城だけに許す。前は城の広い土地の1割、次に川のマス数の5割にしていたが、山城でも大きな堀を引けたので、型で決めた。郭ごとに分けず、城全体で数える。櫓の点数とは別枠
    - 門の前後には引けない（上の `blockedGates`）。ただし、門のすぐ外の1マスに引き、反対側（門の内）が空いた陸なら、その門は引き橋の門になる（下の「引き橋」）。橋の両端にも引けない（下の「橋」）
    - これらの決まりは、引くときには止めず、引いたあとの形で赤く出し、開戦前の確かめで止める。引くときに止めると、塀より先に堀を引けず不便なため（決まりは、開戦するときに満たしていればよい）。引くときに止めるのは、施設・川・堀と重なることだけ
  - 引き橋（`drawbridges`）。門のすぐ外のマスが堀で、反対側が空いた陸なら、その堀のマスは門の引き橋になる。置き物は増やさず、門の前に堀を引くだけで作る。平城は、堀で門の前を守れないと、攻め手がいつも陸づたいに門へ着き、衝車と工兵で門を割る筋が消えなかった（「基本（平城）」を3周探した結果）。施設を強くすると山城・平山城の施設も強くなるので、堀を引ける平城だけに効く仕組みとして足した。現実の平城の引き橋にも合う
    - 開戦前の確かめでは、引き橋を下りた橋（陸）として数える（逃げ道・外周から本丸への道・城の外から門への道・門の前後）
    - 戦いでは上がっていて、ふつうの堀のまま。上がった板が門の外の面をふさぐので、その門に当たるのは、門の中の側の郭（開戦の時に、門の内の隣のマスから、施設と崖をよけて塗った所。大筒のマスと、郭に面したほかの門のマスを含む）から撃った攻撃だけ。引き橋の側や斜め前の陸のほか、塀の外の川や堀から撃っても当たらない（範囲の攻撃も同じ）。攻め手は、その門を寄り道の相手にも選ばない
    - 城の中の側から門を壊すと、引き橋が下りて橋になり、ふつうの速さで渡れる。守り手が自分で下ろすことはなく、上がった引き橋へ出ることもない
    - 引き橋にするのは堀だけ。川の前の門は、今までどおり前後がふさがった門。川のある平山城・山城で使えないようにするため
    - 引き橋の門を壁とみなし、引き橋も上げたまま（堀のまま）でも、外周から陸と橋だけで本丸へ行けること（`hallBreachable`）。外の門をすべて引き橋にしたり、内の門をすべて引き橋にしたりすると、攻め手が入れない城になるため。開戦前の確かめでは、門の前後のすぐあとに見る
    - 逃げ道には引き橋の門も数えるので、本丸の郭の門の片方を引き橋にすると、攻め手が本丸へ入る道を1本にでき、その道の上の出丸が廊下になる（本丸を川の向こうの出島に置き、ほかの三方を堀で囲む形など）。堀を引けるのは平城だけなので、これは平城だけの布陣として認める（逃げ道に引き橋を数えないと、引き橋は逃げ道に使わない余りの門をふさぐだけになり、守りが強くならない）。外から引き橋の門を破れる兵種を、別に考えるかもしれない
    - 見た目：防衛配置では下りた橋（数えるときの形）、攻城では、上がっているあいだは門の前に立てた板、門が壊れると下りた橋
  - 両端が門の橋（地形の橋か引き橋）は、2つの門を、郭から郭へ渡る1つの口とみなす。本丸から門を通って入れるかと、郭の深さを数えるときは、この橋を通り、逃げ道もこの橋を通れる。2つの門は外の門に数えない。川は郭を区切らず城の外の野原とひと続きなので、こうしないと、川や堀の向こうに橋でつないだ出島・馬出しが、本丸から入れない郭になるため。現実の城でも、堀の向こうの馬出しを橋で結ぶ形はよくある。戦いの中の動きは変えない（攻め手は川を歩いて橋に上がれる）
  - 橋は渡れること（`bridgeShut`）。橋を渡る向き（左右が陸なら東西、そうでなければ南北）の両端のマスに、門のほかの施設や堀を置かない。橋は人や荷が渡るもので、渡った先をふさいだ橋は現実にない。門は壊せば通れるので置ける。開戦前の確かめでは、門の前後のすぐあとに見る（通り道の決まりなので）
  - 決まりは、盤面で見えないと直し方が分からないので、防衛配置では、郭を色分けして数に入る土地を濃く塗り、塀の線にないもの・点数を超えた施設・郭の外の施設・近すぎる門・橋をふさいだ施設・引けない所の堀・上限を超えた堀（川から遠いものから数える）を赤く、門へ行けない城の外を薄い赤に塗る。パネルには郭ごとの土地・点数と、城全体の逃げ道・外の門の数をいつも出し、堀を引ける型（平城）では堀の数と上限も出す。堀は、施設と同じく絵のボタンで選ぶ（平山城・山城では押せず、「平城のみ」と出す）。門にマウスを合わせると、門の間かく（`GATE_SPACING`）の円を地面に出し、近すぎる門（`closePairs`）の上に赤い丸と距離を出して、合わせた門と赤い点線で結ぶ（線と丸と距離は、城壁に隠れないよう、地面ではなく重ねる絵に描く）。円は、櫓や鼓楼の効果の範囲（軍の色で塗った円）と取り違えないよう、塗らずに白い長めの点線だけにし、門の案内の札に「白い点線：門どうしの間かく」と、近すぎる門までの距離を書く

## 高低の効果

- 射程：射程が2より長いものは、相手より高い所に立つと、高さの差1段につき射程が `HEIGHT_RANGE_BONUS`（1）マス伸びる（数値は仮）。同じ高さや、相手より低い所からは伸びも縮みもしない。見下ろす利点を表すため、立っている高さそのものでは決めない。攻めも守りも同じ決まり。飛び道具でない家康の軍配や信玄の突撃も、射程が2より長いので同じように伸びる
- 範囲の円は、同じ高さの相手に届く範囲（もとの射程）を出す。低い相手へ余分に届く分は、円には出ない
- 坂：上りは速さが `UPHILL_SPEED`（0.6）倍。下りは普通
- 崖：隣との差が2段以上なら歩けない。矢や弾は越える

## 川と堀

- 川（橋のかかっていない所）と堀には、兵も武将も、攻めも守りも入れる。中では速さが `RIVER_SPEED`（0.1）倍になる（数値は仮）。兵種ごとの差は付けない。川を通れない線ではなく「渡れば損をする所」にし、橋に回り込むか、遅くなるのを承知で渡るかを選ばせるため
- 川や堀の中にいるあいだは、攻撃もスキルも始めない（攻めも守りも、兵も武将も同じ）。渡り切ってから戦う。高低差の「高い所から撃つと射程が伸びる」と同じく、川にも戦いの効果を持たせ、平城で「川を渡らせて、岸から撃つ」守り方ができるようにするため。道の着く先（攻撃する位置）には水のマスを選ばず、攻め手は、水の中から建物（門・大筒など）へ直に入る道も取らない（水の中では壊せないため）。櫓や大筒は、水の中の相手も撃つ
- 経路は、坂と同じく遅さを見込んで選ぶ（川や堀のマスは、ふつうのマスの `1 / RIVER_SPEED` 倍の重み）。斜めに進むときは、角を挟む2マスのどちらかが川や堀なら通れない（斜めに並んだ水の角を抜けて、水を渡らずに越えないため）
- 矢や弾は越える。騎馬の突撃の帯も川や堀を渡る
- 橋のマスは、ふつうの速さで渡れる
- 川と堀には、施設も武将も置けない
- 見た目：堀は、川と同じ水面にし、岸を明るい切り石で舗装して見分ける。岸の壁を切り石の色にし、陸の側に低い縁石を立て（`terrain3d.ts` の `CURB_HEIGHT`・`CURB_WIDTH`）、地面の絵にも縁石の帯と目地を描く。川の岸は暗い石垣のまま。防衛配置では、決まりに外れた堀は水を張らず、地面の高さで赤く出す（半透明の水面の下では赤い印が見えないため）

## 武将の仕様

- 武将は7人（上杉謙信・大島光義・真田昌幸・武田信玄・織田信長・豊臣秀吉・徳川家康）。前田利家（槍将）と服部半蔵（忍び）は外した。外す前に書き出した配置や出撃の予定に2人がいても、読み込むときに黙って飛ばす。武田信玄は馬を降りて軍配を持ち、攻撃は「騎馬の突撃」にした（下の「騎馬の突撃」）
- 武将は役目の名前（猛将・弓将など）を持たず、画面にも文書にも武将の名前だけを出す。能力値の表（`GENERALS`）は `busho` だけを持ち、攻め手の表（`ADEF`）の `name` には武将の名前を入れる
- 攻め・守りのそれぞれで、出せる武将は3人まで（`MAX_GENERALS`）。同じ側に同じ武将は1人まで（守りは `LIMITS`、攻めは `ADEF` の `limit: 1`）
- 武将は兵力を使わない（攻めの `cost: 0`）
- 大島光義の「違い矢」（`src/ui/pixel.ts` の `MON_PIX` の `chigaiya`）は、確かな家紋ではなく仮の印

### 騎馬の突撃

武田信玄の攻撃。風林火山の「風」を元にする。真田昌幸と同じく、軍配で離れた所を指す。
- 信玄はその場で軍配を振り、足元から狙う向きへ、決まった長さ（`charge`）と幅（`radius` の2倍）の帯を出す。溜め（`windup`）が終わった時に、騎馬隊が帯を駆け抜ける
- 騎馬隊は駒ではない。体力はなく、狙われず、兵力も使わない。火計の火と同じ一度きりの攻撃で、溜めが終わった時に、帯の中へまとめて傷を与える
- 騎馬隊の通った跡に土埃が上がり、当たった相手の所で大きく舞い上がって白い輪が広がる。傷は溜めが終わった時に入るので、土埃は演出で、計算には使わない
- 帯は、馬が通れない所の手前で止まる。城壁・崖のほか、攻めでは門と施設、守りでは施設で止まり、守りは味方の門を通り抜ける。塀を飛び越えない。川と堀は渡り、中の相手にも当たる
- 当たるのは、見えている帯の中で、帯の芯から馬が入れる相手だけ。崖の向こうの相手には、帯の幅の内でも当たらない
- 帯の中の建物にも当たる（城壁は壊れない）。建物に当たらないと、攻めの信玄は本丸も門も崩せないため。建物への倍率は `fac`・`hall`
- 射程の内でも、帯が相手に届かないあいだは攻撃せず、届く所まで歩く。守りの信玄は、帯の届く別の相手がいれば狙いを移す

### スキル

武将は、ふだんは通常攻撃をし、一定の間隔でスキルを出す形に、1人ずつ移していく。今スキルを持つのは徳川家康と上杉謙信（下の「徳川家康の軍配」「上杉謙信の回転斬り」）。ほかの武将はスキルの中身を考えながら移す。真田昌幸の火計と武田信玄の騎馬の突撃は、今は通常攻撃のまま。
- スキルは、攻撃の1回分の番を使う。スキルが出せるようになったら、次の攻撃の番をスキルに替える。攻撃を続けたまま、スキルを演出だけで出す形は採らない（体の動きは一度に1つで、絵と計算が食い違うため）
- 番の中身（攻撃かスキルか）は、前の番を終えた時に決める（`nextSkill`）。次の番が来るまでにスキルが出せるようになっていれば、次の番はスキル。構えの途中で攻撃からスキルに切り替わらない。次の番が来る時刻は、そのときの待ちの減る速さ（守りは鼓楼で速まり、足止めで遅れる）のまま減ると見込む
- 戦いが止んで構えを解いたあと（最後の攻撃から、攻撃の間隔に `ATTACK_ENGAGED`（1.5秒）を足した時間を過ぎたあと）は、構えの絵が出ていないので、番の中身をその時の時刻で決め直す。しばらく戦わなかった武将が、出せるスキルを攻撃の番に使ってしまわないため
- スキルの値は能力値として `GENERALS` に書き、攻守の両方に持たせる。間隔は `skillCd`（前のスキルを出してから、これだけ経つと次を出せる）、溜めは `skillWindup`。開戦の時点ですぐ出せる
- スキルを出すと、溜めのあとに効き、効いた時から攻撃の間隔（`cd`）を数え直して、次の番から通常攻撃に戻る
- 仕組みは武将に共通で、スキルを持たない武将の戦いは変えない。スキルの効果は、武将ごとの値（`ward`・`spin` など）で分ける（`src/sim/battle.ts` の `fireSkill`）
- 絵は、スキルを持つ武将だけがスキルの5コマを持つ。区切りは `src/ui/bigBusho.ts` の `SKILL_TIME` で、溜めの長さが武将ごとに違うので武将ごとに持つ。考え方は攻撃と同じ（前の2コマは次の番までの残りで、後の3コマはスキルを出した時刻から出す）。スキルの動きの長さは、コマの数ではなく溜めの長さで決まる。4倍速でもどのコマも描画1回分より長く出るので、1倍速で1コマ67ミリ秒ほど、後の3コマで0.2秒ほどが溜めの下限

### 上杉謙信の回転斬り

上杉謙信は、ふだんは刀で狙った1人を斬り、スキル「回転斬り」で周りをまとめて斬る。
- 通常攻撃は範囲攻撃にしない。前は周りの敵にも6割の傷を与えていた（`cleave`）が、周りへの傷は回転斬りだけにした。`cleave` は使う武将がいなくなったので、仕組みごと外した
- 回転斬りは、短い溜め（`skillWindup`）のあと、足元から範囲（`spinRadius`）の内の敵（武将・兵）に傷（`spin`）を与える。攻めでは、壊せる建物（櫓・大筒・鼓楼・鐘楼・門・本丸）にも、攻めの倍率（`fac`・`gate`・`hall`）を掛けて与える。壊れない城壁には当てない。火計と同じく、塀や崖を挟んでも範囲の内なら当たる
- 溜めのあいだは範囲の円を軍の色で薄く塗り、ふちをなぞる線で残りを示す。斬った時に、白い輪と、少し遅れて金の輪が、範囲のふちへ広がる。溜めのあいだに倒されたら出ない
- 絵のスキルの5コマは、構える・溜める（前の2コマ）、薙ぐ・斬り抜く・残心（後の3コマ）。通常攻撃（頭の上から振り下ろす）と見分けるため、刀はどのコマも胸の下の高さで水平に持ち、横に払う。薙ぐ（手前）と斬り抜く（奥）で、体のまわりに平たい弧を出してひと回りし、斬り抜く・残心では一周の点線の名残を残す。弧（残影）は、通常攻撃の青白い弧と見分けられるよう赤みの色にする

### 徳川家康の軍配

徳川家康は、ふだんは軍配で近くを打ち（射程0.9、`aim` なし）、スキルで味方の受ける傷を減らす。風林火山の「山」を元にする。
- スキルは、攻撃の番のうち、スキルが出せる番で出す（上の「スキル」）。軍配は自分にも掛かるので、味方がいなくても出す
- スキルの溜め（`skillWindup`）のあいだは金の輪が範囲のふちへ広がり、まだ効かない。輪が届くと、周り（`WARD_RADIUS`）の味方に、受ける傷を `ward` の割合だけ減らす効果を掛ける。守りでは建物にも掛かる（壊れない城壁を除く）
- 攻めでは、ほかの武将と同じく敵へ向かう（`pref: 'any'`）。前は一番近い味方について歩いていたが、近くを打つ攻撃では敵に届かないのでやめた
- 効果が掛かってから、金の円と光の筋を出す。溜めのあいだに出すと、効いているように見えるため
- 効果は掛かった相手に付き、`wardTime` のあいだ続く。範囲の外へ出ても、切れるまで続く

### 武将の足し方

1. `src/sim/defs.ts` の型 `GeneralKind` に足す
2. `GENERALS` に能力値を足す
3. `npm run typecheck` が、ほかに足す所（`GDEF`・`ADEF`・`LIMITS`・`SPECS`・`BIG`・説明文など、全員分を求める表）を教えてくれる
4. 型では分からない所は、自分で足す（並び順の配列と `ADEF` の武将の行は `src/sim/defs.test.ts`、家紋は `src/ui/pixel.test.ts` が、入れ忘れを `npm test` で教えてくれる）
   - 並び順の配列 `GENERAL_ORDER`・`UNIT_ORDER`（入れ忘れると、パネルや比較の画面、戦いの判定から黙って抜ける）
   - `ADEF` の武将の行の `general: true`・`limit: 1`（書き忘れると兵として数えられ、人数の上限から外れる）
   - `SPECS` の `mon`（家紋）と、その名前の模様を `MON_PIX` に（書き忘れると幟に家紋が出ない）
5. `npm test` を通し、`npm run balance` の勝ち負けが変わっていないか比べる

## 進め方

### まず基盤、調整は後

いちばん先に、地形などのゲームの仕組みそのもの（基盤）を整える。兵種・武将の数値の調整や、「基本」の城の配置を詰めることは、基盤づくりがひと段落してから行う。仕組みが固まる前に数値を詰めても、仕組みを足すたびにやり直しになるため。

「基本（平城）」の配置と攻城の「基本（平城）」は、ユーザーの依頼で、この例外として詰めた（攻守とも武将なしで、守りと攻めを交互に探した）。「基本（平城）」の城には武将を置かない。配置を探したあとで櫓と大筒の射程を縮めたので、今は攻城の「基本（平城）」で落ちる。武将の射程は変えていないので、武将を出す攻めが有利すぎないかは測っていない。数値や決まりを変えると結果が変わるので、調整のときに見直す。

川を渡れるようにし、川を郭の区切りにしなくしたとき、「基本（平城）」は北を川に任せていたので、川の南岸に城壁を足した。外の塀が長くなった分の外の門（南東 `40,37`）を足し、北東の門を川から1マス南（`40,22`）へずらし、二の丸の広い土地が減って点数を超えた分、北東の弓櫓（`35,22`）を城壁に戻した。探し直してはいない。そのあと、ユーザーの依頼で、守りの強さは見ずに、決まりに合う形に直した。渡れない橋を認めないので、北の橋の出口の城壁を門にし（二の丸へ直に入る門）、門の間かくに合わせて二の丸の西の門を `11,24` から `11,33` へ移した。堀は、西の川の曲がり角 `4,27` から南へ1本（12マス）掘り出し、帯の西の塀の外に沿わせた（南の端の1マスは、堀の西の野原から陸で西の門へ行けるよう陸に残した）。攻城の「基本（平城）」では落ちる（86秒。北の門ができて、前より早い）

そのあと、ユーザーの依頼で、今の決まり（川を渡れる・堀）のもとで、攻めを探す→守りを直す、を3周し（攻守とも武将なし。守りは施設・門・堀を動かした）、3周目の守りを「基本（平城）」に、それをいちばん速く落とした作戦を攻城の「基本（平城）」にした。外の門は西と南東から南の塀（`10,40`・`36,40`）へ、二の丸の南の門は `26,35` から `29,35` へ移り、堀は北の川の北岸に4マス・西に1マス増えた（16マス）。周ごとに、その周の強い攻めは止まるが、探し直すと衝車と工兵で門を割る筋が別の門に見つかり、3周では勝ち筋が消えなかった（総当たりで落とせた作戦は 642 → 255 / 約1470）。攻城の「基本（平城）」は、南西の口から衝車6と工兵15を出し、南の門（`10,40`）を割って70秒で落とす。北岸の堀が効いているかは測っていない

そのあと、ユーザーの作った配置を元に、「基本（平城）」を置き換えた。本丸を北の川の向こうの出島（二の丸）に置き、出島の西・北・東を堀で囲み、北の門（`32,9`）を引き橋の門、南の門（`20,19`）を橋で南の郭の門（`20,21`）とつなぐ形（上の「引き橋」の、平城だけの布陣）。前の城の塀は、川の南の出丸2つとして残る。攻守とも武将なしで、門を近い順に1つずつ割る作戦を段ごとに探し（各段で時間と兵力の少ない上位を残して次の門へ進む）、行き詰まった所で、どこで倒されているかと、施設を1つずつ外したら届くかを調べた。兵力60では、本丸の手前の門までは割れるが、門に兵力の9割を使い、本丸を削れなかった。兵力80なら落ちる作戦が見つかったので、それを測る相手にして守りを強くした（施設・門を動かし、減らしていない。南東の外の門を `36,40`→`37,40`、弓櫓を `33,35`→`30,35`・`19,40`→`15,40`、鼓楼 `29,25` を大筒にして `28,31`、鼓楼を `18,30`→`16,29`）。守りを直すたびに攻めを探し直したが、兵力60でも80でも本丸に傷を付ける作戦は見つからなかった。攻城の「基本（平城）」には、いちばん奥まで進んだ作戦（北の口から衝車2と盾兵10を出して川を渡り、橋の上から `20,19` を割る。本丸の傷0%）を登録した。テストは「落とせないが、`20,19` を割る」を確かめる。見つからなかっただけで、落ちない城と分かったわけではない

### 「基本」の平山城・山城

「基本」の平山城・山城と、攻城の「基本（平山城）」「基本（山城）」も、ユーザーの依頼で上の例外として探した（攻守とも武将なし）。
- 平山城：段差が台地（高さ2）の縁の1本だけなので、外の塀（三の丸）を台地の縁に沿わせ、内の塀（二の丸）を台地の中に巡らせた（内の塀を台地の縁に沿わせる形も試したが、点数が倍近くになり、勝ち筋も残った）。勝ち筋を探して消すことを3周し、最後の配置を登録した。そのあと攻めを長めに探しても落とせる作戦は見つからなかったので、攻城の「基本（平山城）」には、本丸にいちばん迫った作戦（本丸の傷44%）を登録した。テストは「4割より多く削る」を確かめる。本丸は台地の西の縁に近く、二の丸の西の端に寄っている
- 山城：塀を段差に沿わせ、内の塀（二の丸）を高さ3の縁に、外の塀（三の丸）を高さ2の縁に巡らせた。勝ち筋を探して消すことを3周し、最後の配置を登録した。そのあと攻めを長めに探しても落とせる作戦は見つからなかったので、攻城の「基本（山城）」には、本丸にいちばん迫った作戦（本丸の傷96%）を登録した。テストは「9割より多く削る」を確かめる

どちらの作戦も落とせないと分かっている作戦なので、テストも「落とせる」ではなく、本丸をどれだけ削るかを確かめる。見つからなかっただけで、落ちない城と分かったわけではない

川を渡れるようにしてから、攻城の「基本（平山城）」は、東の口の攻め手が城の東の川を渡って櫓に撃たれ、本丸を削れなくなった（44%→0%）。攻城のシミュレーション（作戦の探し直し）は、防衛施設と配置の決まりの検討が終わってから行うので、それまで平山城のテストは止めている（`src/sim/plan.test.ts`）

探したあとで門の間かく（`GATE_SPACING`）の決まりを足したので、決まりに合うよう門を2つずつ動かした（山城は外の門 `6,15`→`12,8`・`6,16`→`5,22`、平山城は内の門 `21,14`→`26,13`・外の門 `34,18`→`34,21`）。基本の作戦との結果（本丸の傷）は変わらないことを確かめたが、ほかの攻め方に弱くなっていないかは探し直していない

### 基盤づくりのあとに取り組むこと

次のことは、数値の調整のために必要だが、基盤づくりがひと段落するまで後回しにする。それまでは、次の作業の候補にしない。
- 兵種の数値を、自動で何度も戦わせて確かめる仕組み（`npm run balance` を使う）

### 取り下げたこと

次のことは、現時点では課題から取り下げた。頼まれるまで、次の作業の候補にしない。
- 山城で、通れる道と通れない道を分ける
- 施設の堀。川と同じく通れなくし、川に1か所でも接していないと開戦できない形を考えたが、配置が複雑になるため、施設ごといったん外した。今の堀は、施設ではなく地面の層（配置記録の `moat`）として入れ直したもので、通れない線ではなく遅い所にした（上の「川と堀」）。外す前に書き出した配置の施設の堀は、今も読み込むときに黙って飛ばす
- 施設の拒馬（騎兵と騎馬の武将を止め、ほかの攻め手の足を鈍らせる）。野戦の道具で、城の守りには合わないため、施設ごと外した。外す前に書き出した配置に拒馬があっても、読み込むときに黙って飛ばす

### PC が中心

動きを確かめるのも作り込むのも、PC のマウス操作を前提にする。スマホは「壊れていなければよい」くらいにゆるく考え、必要になったら詰める。

### キーボード操作は今は足さない

防衛の盤面で、矢印キーでマスを選び、施設や武将を置く・つかむ・消す操作（`src/ui/app.ts` の `actAt`・`placeByKeyboard` など）はコードに残っているが、新しく足したり作り込んだりはしない。壊していないかはテストで見る程度にし、ユーザーに頼む確認項目には入れない。

元に戻す・やり直す（Ctrl＋Z・Ctrl＋Y）と、攻城の一時停止（スペースキー）は、この対象の外。

### 武将と兵の大きな絵

武将の7人全員（上杉謙信・織田信長・大島光義・真田昌幸・豊臣秀吉・徳川家康・武田信玄）と、兵の7種（歩兵・弓兵・騎兵・衝車・工兵・盾兵・斥候）を、動きの多い大きな絵で描く（`src/ui/bigBusho.ts`）。作り方は `docs/development.md` の「武将の大きな絵を作り直す」。下の決まりは、とくに断らないかぎり兵にも当てはめる。ユーザーと決めたこと：
- 3頭身・背丈38ドット（前立てや髷を含む。高い前立てや髷が目印の武将は、40ドットほどまで許す。秀吉の放射状の後立て、家康の歯朶の前立ての輪、信玄の白熊の毛と鍬形は背丈に数えず、頭のまわりに大きく広げる）。絵の枠は 80×72 で、まわりは武器を振る余白
- 兵は武将の半分ほどの大きさで、背丈20ドットほど（陣笠などを含む）。騎兵は28ドット、衝車は26ドットほど。絵の枠は、騎兵と衝車も含めて 56×48。頭は20ドット用に1ドットずつ手で置く。兵は群れで出るので、武将と区別がつくよう簡単にする：顔の部品は描かず肌の面と輪郭だけにし、色は軍の色・黒・肌・木を中心に2段にまとめ、着物・腕・腿は軍の色の暗い段、脚絆と草鞋は黒にする。兵は幟を持たず、前立てや金の飾りも付けない。胴など、兵ごとに決めた所を軍の色に塗る。体力の棒は頭の上の端（`top`）の上に出す。兵ごとの形と攻撃のコマ：
  - 歩兵：陣笠・槍。軍の色は胴・草摺・合印。構える・引く・突く・伸ばす・戻す
  - 弓兵：陣笠・和弓（上が長く下が短い）・背中の矢筒。光義と同じく弓を前へ突き出して引き絞り、矢は引き絞ったときの弓の握りから出す（絵のデータの `muzzle`）。つがえる・引き絞る・放つ・残身・下ろす
  - 騎兵：兜（黒い鉢・眉庇・吹返し・軍の色の縅の錣。前立てなし）・槍で、黒鹿毛の馬に乗る。軍の色は胴・草摺・合印・障泥。馬の胴は前の向き（斜め前は右下、斜め後ろは右上）へ少しだけ傾け、地面も同じだけ傾けて脚の長さをそろえる（前の向きそのものまで傾けると、前脚と後脚の長さがそろって見えない）。枠に収めるため、待機と歩きでは槍を肩に担ぐ。倒れは横へ回さず、馬が膝をついて沈む。構える・引く・突く・伸ばす・戻す
  - 衝車：軍の色の屋根・柱・土台・4つの車輪と、縄で吊るした丸太。左右の幅（丸太が出入りする口）を広めにする。歩きは車輪が回り、倒れは転がらずにその場で潰れる。引く・溜める・突く・打ちつける・戻す
  - 工兵：鉢巻・白木の槌。構える・振りかぶる・打ち下ろす・打ち込む・戻す
  - 盾兵：陣笠・体の高さほどの置盾。軍の色は胴・草摺・合印・盾の帯。盾で押す（構える・引く・押す・押し込む・戻す）
  - 斥候：手ぬぐい（軍の色）と帯の軽装で、持ち物なし。囮で傷を与えないので、攻撃のコマは手を振って誘う（手を上げる・振る・振る・振る・下ろす）。盤面の斥候は攻撃しないので、このコマは盤面には出ず、確かめのページの「攻撃」でだけ見られる（「戦い始め」では、着いたあと待機の姿のまま）
- 描く向きは、斜め前（右前を向く）と斜め後ろ（右後ろを向く）の2つ。左向きは反転して作る。向きによって構える側が入れ替わるのは許容する
- 待機は武器を構えた姿。武器は、どの向きでも画面の左に立てる（謙信は八相・左肩の横、信長は鉄砲を立てて持つ、光義は弓を立てて持つ、昌幸は軍配を立てて持つ、秀吉は謙信と同じ刀の構え、家康と信玄は昌幸と同じく軍配を立てて持つ。家康は攻撃で軍配を振りかぶって打ち下ろし、スキルで昌幸と同じく軍配を掲げて指す）。斜め後ろでは、体の前にある手と武器の根元を背中に隠す。弓と軍配は、待機では画面の左の手で立て、攻撃では狙う向きの側の手で握るので、向きによって待機と攻撃で持つ手が入れ替わる
- 動きは、各向きに待機4・歩き4・攻撃5・被弾2・倒れ3コマ。スキルを持つ武将は、スキルの5コマも持つ（上の「スキル」）。攻撃は「前の2コマ（次に攻撃できるまでの残りで出す）」と「後の3コマ（攻撃した時刻から出す）」に分け、区切りは `src/ui/bigBusho.ts` の `ATTACK_TIME`。4倍速でも、どのコマも描画1回分（16.7ミリ秒）より長く出る
- 構えるかどうかは、武器の特性として分ける。飛び道具（鉄砲・弓）の武将は、能力値の構える時間（`aim`）を持ち、しばらく撃っていなかったら構えてから撃つ。兵は弓兵も `aim` を持たず、近くで戦う武器と同じく前の2コマを出さずに1回目を撃つ（`aim` を足すのは能力値の変更なので、絵のためには足さない）。近くで戦う武器（刀・槍など）の武将は `aim` を持たず、敵の前に着いたらすぐ攻撃する。軍配（昌幸の火計・信玄の騎馬の突撃）は飛び道具ではないので `aim` を持たない（どちらも、円や帯が出てから当たるまでの溜めがすでにある）。家康は軍配で近くを打つので、近くで戦う武器と同じく `aim` を持たない。スキルも `aim` を持たない（溜めがすでにある）。そのため、近くで戦う武将と軍配の武将の1回目の攻撃は前の2コマを出さず、後の3コマ（刀なら踏み込み斬り）から始まる。続けて攻撃しているあいだは、どちらも前の2コマから出る。まだ攻撃していない武将（開戦前や、持ち場で敵を待つ守り）は、構える時間のあいだのほかは待機の姿のまま。当たる時刻は戦いの計算だけで決まり、絵はそれに合わせてコマを選ぶ
- 武将の頭は38ドット用に1ドットずつ手で置く（縮めた形にしない）。顔は、目を白目と黒目の2ドット（黒目は進む向きの側）、眉を目の上の暗い横線、ひげを髪より明るい茶（白髪の光義は、髪より少し明るい白）、口を赤みの1ドットにして、点が何か分かるようにする
- 細かすぎる模様は減らし、その武将の目印（謙信の白い頭巾と金の前立て、信長の茶筅髷と赤いマント、光義の金の鍬形と長い白髪・白いひげ・背中の矢筒、昌幸の高い金の二本の前立てと赤い緒・生成りの縁の黒い陣羽織・橙の袖、秀吉の放射状の金の後立てと高い黒い兜・赤い鎧・紫の袖・背中の×の紐、家康の歯朶の前立ての輪と赤い鉢巻・白い陣羽織と金の広い襟、信玄の白熊の毛と金の鍬形・武田菱・赤い陣羽織など）を際立たせる
- 敵味方は、背中の幟（家紋と軍の色の帯）で見分ける。朱や赤の飾りも軍の色に塗り替える。幟は字が裏返らないよう反転しない。体力の棒は幟の上に出す
- 防衛と攻城のパネルの武将と兵のボタン（とドラッグ中の絵）と、兵種の画面の表の動きの欄は、大きな絵から全身を等倍（1ドットを画面の1点）で切り出す（`bigBodyBox`）。縮めるとドットが潰れるため。パネルのボタンは横44×縦60ドット（左右の余白を詰め、名前を兵や施設と同じ書き方で1行に出す）、兵種の画面は60ドット四方。パネルでは止まっているときは待機の構え、歩くときは歩きのコマ、兵種の画面では歩き・攻撃・倒れを順に見せる。兵の絵は切り出す枠より低いので、縦は下にそろえて置く。横は、武将と同じく絵の真ん中を切り出す。
- 鉄砲の火花と煙は絵の側に描き、弾は肩の高さの銃口から、矢は引き絞った弓の握りの高さから出す（`BIG_MUZZLE`）
- 描いた絵は、まず画像とモーションの確かめのページで見せ、ユーザーの確認を得てからマージする。盤面と確かめのページは同じ表（`bigBusho.ts` の `BIG`）を読むので、確認はブランチの上で行う
