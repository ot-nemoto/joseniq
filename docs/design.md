# 方針と決まり

JOSENIQ を作るうえで決めたことをまとめる。動きや決まりを変えるときは、この文書も同じ PR で直す。

## 守る決まり

### 武将の能力は、攻めと守りで同じにする

武将の能力値（体力・威力・射程・速さ・特徴の倍率など）は、攻める側と守る側でいつも同じにする。釣り合いが崩れても、片方の武将だけを弱めたり強めたりして直すことはしない。釣り合いは、兵種・施設・配置・AI の動き・編成例などで取る。
- コードでは、能力値を `src/sim/defs.ts` の `GENERALS` に1つだけ書き、守り（`GDEF`）と攻め（`ADEF`）の両方がそれを使う
- 守りにだけある値（敵を見つける範囲 `aggro`、持ち場から離れられる距離 `leash`）は、能力値ではなく守り方の設定なので、決まりの外。ただし変えるときは確かめる
- 攻めにだけある値（施設・本丸への倍率 `fac`・`hall`、狙うものの好み `pref`）も、攻め方の設定として扱う

### 武将は特別枠

- 武将は9人（猛将・弓将・軍師・槍将・騎馬大将・鉄砲大将・築城名人・忍び・堅守）。それぞれ戦国の人物の名前を持つ
- 攻め・守りとも、出せるのは合わせて3人まで（`MAX_GENERALS`）。同じ武将は1人ずつ
- 武将は兵力を使わない
- 大島光義の「違い矢」と服部半蔵の「手裏剣」は、確かな家紋ではなく仮の印
- 武将を足すときは、`src/sim/defs.ts` の `GENERALS` に能力値を足す。ほかに足す所（守り・攻めの設定、見た目、説明文）は、武将ごとの表がどれも型で全員分を求めているので、`npm run typecheck` が教えてくれる
- 新しい特徴は、その武将がいない戦いの結果が変わらないように入れる（編成例の勝ち負けが、変える前と同じかで確かめる）

### 数値は仮

兵種・施設・武将の数値は、今はどれも仮の値。数値の調整は、別に時間を取って行う。仕組みを足したときに釣り合いの実績（`npm run balance:combos`）を取るのは、影響を見るためで、その結果からすぐに数値や配置を直すことはしない。

## 進め方

### まず基盤、調整は後

先に、地形などのゲームの仕組みそのものを整える。兵種・武将の数値の調整や、「基本」の城の配置を詰めることは後回しにする。仕組みが固まる前に数値を詰めても、仕組みを足すたびにやり直しになるため。

### 今は取り組まないこと

次の2つは課題から取り下げた。頼まれるまで、次の作業の候補にしない。
- 兵種の数値を、自動で何度も戦わせて確かめる（`npm run balance`）
- 山城で、通れる道と通れない道を分ける

### PC が中心

動きを確かめるのも作り込むのも、PC のマウス操作を前提にする。スマホは「壊れていなければよい」くらいにゆるく考え、必要になったら詰める。

### キーボード操作は今は足さない

防衛の盤面をキーボードで操作する機能はコードに残っているが、新しく足したり作り込んだりはしない。壊していないかは、テストで見る程度でよい。

## 見た目

- 武将と兵の体は、28×28 のドット絵の板のまま。武器・兜の前立て・幟（衝車の丸太も）だけを立体にする（`src/ui/gear.ts`）
- 建物は、模様の貼り絵と形の作り込みで見せる。カメラは遠近投影で、画角は狭め（30°）
- 試して採らなかったもの：駒をボクセルにする、高画質の後処理（GTAO・やわらかい影）、武将を 56×56 で描き直す。見比べた結果、ドット絵の板のほうが全体のまとまりがよかった。作り込むなら、持ち物の立体や建物の側で行う
