# 作り

コードの全体の見取り図。ファイルごとの細かい説明は、各ファイルの先頭のコメントに書いてある。

## 全体

Vite で組む、サーバーのない1ページのアプリ。

| ファイル        | 役目                                                                                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.html`    | 画面の骨組み。タブ・パネル（`panelEdit`・`panelBattle`・`panelTerrain`）・兵種の画面（`unitsView`）・結果の窓（`overlay`）などを静的に書いてある。フォントは Google Fonts から読む |
| `src/main.ts`   | 入口。`style.css` を読み込み、`src/ui/app.ts` の `startApp()` を呼ぶ                                                                                                               |
| `src/style.css` | 見た目全体と、色の変数。盤面の色も、この変数を `renderer.ts` の `PAL_VARS` が読む                                                                                                  |
| `src/assets/`   | 画像（`emaki.svg` は `style.css` の背景）                                                                                                                                          |

コードは2つに分かれている。

| フォルダ   | 役目                       | 使ってよいもの                                             |
| ---------- | -------------------------- | ---------------------------------------------------------- |
| `src/sim/` | 配置の決まりと、戦いの計算 | 純粋な TypeScript だけ。DOM・three.js・`window` を使わない |
| `src/ui/`  | 画面・入力・3D の表示      | `src/sim/` と three.js と DOM                              |

`src/sim/` は画面に頼らないので、テスト（vitest、node で動く）や、調整のスクリプト（`scripts/`、Vite の `ssrLoadModule` で `src/sim/index.ts` を読む）から、そのまま動かせる。`src/sim/` から `src/ui/` を読み込まない。この分け方は型チェックでも Biome でも止まらないので、書くときに気をつける（テストは node で動くので、DOM を使うと落ちることが多い）。

### 戦いの計算の流れ

計算の単位はティック（`DT`＝1/30 秒）。
1. `createBattle(layout)` で、配置データから戦いの状態を作る（施設・守りの武将・本丸・地形）
2. 出撃は、出撃の並び（`PlanStep[]`）を `deployDue` が開戦からのティックどおりに `deploy` する。画面では、攻城の予定（`Draft`）を `draftToPlan` で並びに直して使う
3. `step` の中は、飛んでいる飛び道具を進めて届いたものを当てる → 鐘楼が攻め手を見つけて鳴る（`ringBells`。見つけた攻め手を `bell` に入れ、守将が駆けつける） → 櫓と大筒が撃つ → 守りの武将が動く → 攻め手が動く → 倒れた攻め手と守将を外す → 効果や記録の時間を進める、の順（壊れた施設は外さずに残す）
   - 飛び道具（矢・鉄砲の弾・大筒の玉。`shot` を持つ施設・兵・武将が撃つ）は、撃った時に `shots` に入れ、届いた時に傷を入れる。速さは `SHOT_SPEED`。どれも、相手が前のティックの速さ（`vx`・`vy`）のまま進むとして、届く時にいるはずの場所へ飛ぶ。矢と鉄砲の弾は、落ちた所から `SHOT_HIT_RADIUS` の内に相手がいれば当たり、いなければ外れる（届く前に相手が倒れたときも外れる）。外れた矢は地面に刺さり（効果 `stuck`）、外れた弾は何も残さず消える。鉄砲・大筒を撃つと、撃った所に効果 `smoke`（火花と煙。見た目だけ。大筒は大きく長く残る）を出す。大筒の玉は、落ちた所で弾けてまわりに当たる。戦いが終わったら、飛んでいるものは届かない。`shot` を持たないものは、撃ったその場で当てる
4. 勝ち負け
   - 本丸が落ちたら、その時点で `win` に決まる（そのティックの残りの動きは続く）
   - `step` の最後で、`timeLimit`（ふだんは `TIME_LIMIT`）を過ぎていれば `timeout`
   - `step` の最後で、攻め手がいなくなり（攻め手の飛び道具も届き終え）、もう出せる兵も武将もなければ `wipe`（出撃できるのは開戦から `PLAN_LIMIT`＝2分までなので、2分を過ぎて攻め手がいなくなったときも `wipe`）
   - `runPlan` だけは、予定を出し切って攻め手がいなくなった時点でも `wipe` にする（`autoStep`。攻め手の飛び道具が届くまでは待つ）。画面は、兵力が残っていて2分を過ぎていない限り続ける。そのため、同じ配置と予定でも、画面と `runPlan` で終わり方が変わることがある

戦いの計算には乱数を使わない。同じ配置と同じティックの出撃なら、同じ結果になる（同じブラウザなら）。地形だけは乱数を使う。居城の移転では種に今の時刻を使うが、作った地形は配置データ（`heights`・`water`・`bridge`）に入れて保存するので、戦うたびに作り直すことはない。

### 状態とモード

- 状態（配置 `layout`・攻城の予定 `siege`・戦い `battle`・モード `mode`・選んでいる道具 `tool` など）は、`startApp()` の中の変数として持つ
- モードは防衛（`edit`）・攻城（`battle`）・兵種（`units`）の3つで、`setMode` で切り替える。攻城に入るたびに `newBattle()` で `createBattle(layout)` を作り直し、ほかのモードでは戦いを持たない
- 動作の見本は、兵種の画面の「動作」ボタンから開く窓（`sampleDialog.ts`）。窓の中に盤面をもう1つ作り（`createRenderer`）、見本の戦いと、一時停止・速さ（0.25×・0.5×・1×）を、攻城とは別に持つ。盤面を左クリック（ほとんど動かさずに離す）すると、押したマスを見本の相手の新しい場所にする。窓が開いている間だけ、自分で `requestAnimationFrame` を回して `stepSample` と描画を繰り返す
- 「開戦」を押すと戦いが始まる（`battle.started`）。`runPlan` では、最初の出撃で始まる

### 毎コマの流れ

画面は `requestAnimationFrame` で毎コマ `loop` を回す。攻城で戦いの途中なら、経過時間×速さの分だけ、ティックごとに `deployDue` と `step` を繰り返す（1コマで多くても40ティック。一時停止中は進めない）。そのあと `renderer.draw` で描く。

### 入力の流れ

盤面のマウスの操作は `app.ts` が受け、`renderer.tileAt` でマスに直し、`src/sim/` の `place` などで決まりを確かめて配置を変える。右ドラッグ・中ドラッグ・ホイールは `orbit.ts` が受ける。左ボタンでも、空いている所を押したときは、`app.ts` が `orbit.ts` に盤面を動かさせる。

### 盤面の描き方

- 地面の上の平らなもの（市松・城域・川・射程の円・影など）は、Canvas 2D で地面の絵に描き、地形の上面に貼る
- 建物は立体（`models.ts`）、武将と兵はドット絵をこちらに向けた板（Sprite）
- 体力のバー・数・飛び道具（矢・鉄砲の弾・大筒の玉）・斬撃は、盤面の上に重ねた別の canvas に描く。飛び道具は今の位置に描き、進んだ割合に合わせて、矢と大筒の玉は山なりに持ち上げる。櫓から撃ったものは建物の上から、大筒の玉は筒の口から撃ち出す。大筒の模型は、施設が記録した最後に撃った向き（`aimX`・`aimY`）へ回す。矢と大筒の玉の影は地面の絵に描き、落ちる場所へ向かって進む。矢は、矢柄・鏃・撃った側の色の矢羽根で矢の形に描き、外れて刺さった矢も同じ形で少しのあいだ地面に残す。鉄砲の弾は光る筋で描く。鉄砲・大筒を撃った所には一瞬の火花と、広がりながら上って薄れる煙を描く
- 武将と兵の顔の左右は、歩いた向きか攻撃した向きの、新しいほうに向ける（止まって攻撃しているあいだは相手の方を向き、歩き出したら歩く向きに戻る）。three.js の板は横の大きさをマイナスにしても左右に返らないので、左を向くときは左右に返した絵を貼る

## データと保存

### 配置データ（防衛）

`Layout`（`src/sim/layout.ts`）を、そのまま JSON にしたもの。
- `buildings`：施設の種類と位置（本丸は左上の位置）
- `generals`：守りの武将の種類と位置
- `heights`・`water`・`bridge`：地形（盤面のマスごとの高さ・川・橋。ないときは平らで川なし）
- `map`：地図の型の名前

防衛の「配置データ（JSON）」の書き出しと読み込みで使う。読み込むときは `validate` で、置くときの決まり（城域・重なり・個数・本丸の置き場所・地形）に合うかを確かめ、合わないものは読み込まない。今は外している堀と拒馬が入っていれば、それだけを飛ばして読む。開戦できるか（本丸への道・門の前後・守り手が入れない施設・塀と郭）は確かめないので、開戦できない配置でも読み込める（`notReady` で別に見る）。

### 攻城の出撃の予定（出撃記録）

`Draft`（`src/sim/plan.ts`）を JSON にしたもの。
- `version`：形の版（今は 1。違えば読まない）
- `gates`：口の位置
- `rows`：出撃の行。何番目の口から、何を、何体、開戦から何秒に、何秒おきに出すか（武将は1体だけ）。行の最後の1体が出る時刻（開始＋間隔×（数−1））は `PLAN_LIMIT`（2分）まで。画面の入力欄の上限は、ほかの欄から決まる（`rowNByTime`・`rowT0Max`・`rowDtMax`）。時刻の判定は、出撃と同じくティックに丸めて行う（`afterPlanLimit`）。読み込むときは、2分を超える分の数を減らし、開始が2分より後の行は外す（`sanitizeDraft`）。前の形の出撃記録（出撃の一覧）を読み込むときは、`addDeploys` が2分より後の出撃を入れない

攻城の「出撃記録（JSON）」で使う。戦ったあとに書き出すと、手で出した兵や武将も予定の行にまとめる。まとめるときに出撃の時刻や位置を少し寄せるので、手で出した戦いを1ティックまで同じに再現するものではない。予定と合わせて兵力・武将の人数を超えたり、同じ武将がすでに予定にいたり、開戦から2分より後だったりする手の分は入れず（`addDeploys` が入れなかった数を返す）、その数を知らせる（手で出せるのは2分までなので、画面からは2分より後の手の分はできない）。

予定を入れ替えたとき（読み込み・基本・全消去）と、戦いを作り直すとき、手で出した分をまとめて書き出すときは、今の地形で口にできない口（口のマスか、辺に沿った±2マスが平地でない・川）を、いちばん近い口にできるマスへ動かす（`src/ui/app.ts` の `snapGatesOf`）。

### ブラウザへの保存

`localStorage` に2つ保存する（`src/ui/app.ts`）。

| 鍵                     | 中身                                                                  |
| ---------------------- | --------------------------------------------------------------------- |
| `kozen-enbu-layout-v8` | 防衛の配置データ                                                      |
| `kozen-enbu-siege-v2`  | 攻城の出撃の予定（読むときに `sanitizeDraft` で今の決まりに合わせる） |

形を変えて前のデータが読めなくなるとき、または同じ形でも意味が変わるとき（盤面の大きさを変えたときなど）は、鍵の末尾の版を上げる。省いてよい項目を足すだけなら上げない。

## テスト

- `src/sim/*.test.ts`：配置の決まり・戦い・出撃の予定・地形と、定義の表（武将の能力値が攻守で同じか、並び順の配列に全員が入っているか）を確かめる
- `src/ui/*.test.ts`：画面のうち、DOM なしで確かめられる所（ドット絵・持ち物・動き・カメラ）だけ
- テストの設定は `vite.config.ts` の中にある（node で動かす）
- 画面の操作は自動のテストがないので、手で（または Playwright で）確かめる
